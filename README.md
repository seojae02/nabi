# Nabi

외국인이 한국 생활에서 겪는 병원·행정·주거 등의 문제를 자신의 언어로 질문하고, 필요한 정보와 다음 행동을 안내받을 수 있도록 만든 생활 지원 서비스입니다.

**배포:** https://nabi-korea.vercel.app  
**지원 언어:** 한국어 · English · Tiếng Việt · 中文

---

## 1. 문제

한국에 거주하는 외국인은 생활하면서 다양한 정보를 찾아야 하지만, 단순히 한국어를 이해하지 못하는 것만이 문제는 아닙니다.

예를 들어,

- 주소가 변경되었을 때 어디에 신고해야 하는지
- 병원에 갈 때 어떤 서류가 필요한지
- 몸이 아플 때 어느 진료과로 가야 하는지
- 행정 업무를 처리하려면 어느 기관을 방문해야 하는지
- 창구 앞에서 자신의 상황을 어떻게 설명해야 하는지

와 같이 **자신의 상황에 맞는 절차와 기관을 직접 찾아야 하는 과정**에서 어려움을 겪을 수 있습니다.

기존 서비스도 각각의 역할은 있지만 한계가 있습니다.

| 기존 수단 | 한계 |
|---|---|
| 번역기 | 문장 번역은 가능하지만 어떤 절차를 밟아야 하는지는 알기 어려움 |
| 지도 | 기관의 위치는 확인할 수 있지만 방문 전에 준비할 사항까지 알기 어려움 |
| 일반 챗봇 | 답변의 근거를 확인하기 어렵고, 행정·체류·계약과 같이 상황에 따라 달라지는 문제는 추가 확인이 필요함 |

Nabi는 이러한 문제를 **질문 → 필요한 정보 확인 → 방문 장소 확인 → 창구에서 사용할 문장 확인 → 필요시 기관 연결**의 흐름으로 해결해보는 것을 목표로 했습니다.

## 2. 핵심 기능

### ① 자기 언어로 질문

사용자가 한국어를 잘하지 못하더라도 자신의 언어로 생활 관련 문제를 질문할 수 있습니다.

- 한국어 / 영어 / 베트남어 / 중국어 지원
- 멀티턴 채팅
- 음성 입력
- 후속 질문 제공
- 답변과 관련된 출처 표시

사용자가 처음부터 자신의 문제가 행정, 의료, 주거 중 어디에 해당하는지 선택하지 않아도 질문 내용을 바탕으로 관련 정보를 확인할 수 있도록 구성했습니다.

### ② 필요한 정보와 다음 행동 안내

답변을 단순한 설명으로 끝내기보다 실제로 다음에 무엇을 해야 하는지 확인할 수 있도록 구성했습니다.

1. 핵심 내용
2. 필요한 서류 및 조건
3. 어디에서 어떻게 처리하는지
4. 주의할 사항
5. 참고 출처

기관명이나 서류명은 가능한 경우 한국어 원문을 함께 표시해 실제 창구에서 확인할 수 있도록 했습니다.

### ③ 창구 앞에서 사용하는 도구 세 가지

답변을 읽는 것만으로는 부족한 경우가 있습니다. 실제로 어려움을 겪는 시점은 기관에 도착한 다음이기 때문에, 세 가지 도구를 채팅 입력창 위에 항상 표시해 답변을 기다리지 않고도 사용할 수 있도록 했습니다.

#### 시설 안내받기

방문이 필요한 기관을 확인할 수 있습니다. 주민센터, 출입국·외국인청, 보건소, 병원, 약국, 경찰서, 세무서, 은행 등 8곳을 기본 목록으로 제공합니다.

여기에 더해 **대화 내용을 바탕으로 어떤 기관 또는 진료과가 필요한지 함께 안내합니다.** 의료 질문의 경우 `병원`이라는 넓은 범위 대신 해당하는 진료과를 제시합니다.

| 질문 내용 | 안내되는 곳 |
|---|---|
| 두통이 계속된다 | 내과 · 가정의학과 · 응급실 |
| 지난주에 넘어져 손목이 아프다 | 정형외과 · 가정의학과 |
| 이사 후 전입신고를 해야 한다 | 주민센터 · 출입국·외국인청 |

증상만으로 진료과를 하나로 좁히기 어려운 경우에는 **해당될 수 있는 곳을 모두 표시하고, 가정의학과를 먼저 안내합니다.** 하나를 임의로 선택해 단정하지 않도록 구성했습니다.

이 안내는 진단이 아니며, 화면에서도 그렇게 읽히지 않도록 목록 아래에 접수처에서 확인하도록 안내 문구를 함께 표시합니다.

선택한 기관은 현재 위치를 기준으로 검색하며, 위치 확인이 어려운 경우에도 네이버·카카오·구글 지도 링크로 이동할 수 있습니다.

#### 내 상태 한국어로

한국어로 자신의 상황을 설명하기 어려운 경우, 지금까지의 대화를 바탕으로 창구에서 사용할 수 있는 한국어 문장을 만들어줍니다.

예:

> 저는 한국어를 잘 못합니다. 이틀 전부터 배가 많이 아픕니다. 밥을 먹고 나면 통증이 더 심해집니다. 집에서 가져온 진통제를 먹었지만 효과가 없었습니다.

화면에 크게 표시해 직원에게 그대로 보여줄 수 있습니다. 또한 **사용자가 자신이 무엇을 보여주고 있는지 확인할 수 있도록 같은 내용을 사용자의 언어로도 함께 표시합니다.**

대화에 없는 내용은 만들어내지 않으며, 이름·등록번호·연락처와 같은 식별 정보는 사용자가 입력했더라도 문장에 포함하지 않습니다.

#### 번역기

안내문의 한 문장이나 창구에서 물어볼 질문을 바로 번역할 수 있습니다. 사용자의 언어와 한국어 사이를 양방향으로 전환할 수 있으며, 결과를 복사할 수 있습니다.

번역 내용은 대화 기록에 포함되지 않습니다. 번역한 문장이 이후 답변에 영향을 주지 않도록 분리했습니다.

### ④ 필요한 경우 기관 연결

AI가 직접 판단하기 어려운 문제는 관련 기관에 확인할 수 있도록 안내합니다.

예를 들어 진단이나 의료적 판단, 법률적 판단, 체류자격 관련 심사 결과 등은 AI가 결과를 단정하기보다 관련 기관에 문의하는 방향으로 구성했습니다.

또한 119, 112, 1339, 1345, 132 등의 연락처를 제공하고, 응급 상황으로 판단되는 경우 관련 연락 수단을 먼저 확인할 수 있도록 했습니다. 기관 목록은 외부 요청 없이 동작하므로 네트워크 상태와 관계없이 전화번호를 확인할 수 있습니다.

## 3. 서비스 이용 흐름

```text
사용자 질문
    ↓
자기 언어로 상황 설명
    ↓
관련 정보 및 출처 확인
    ↓
필요한 서류·조건 확인
    ↓
방문해야 할 기관 · 진료과 확인
    ↓
창구에서 사용할 한국어 문장 확인
    ↓
AI만으로 해결하기 어려운 경우
관련 기관·전화번호 안내
```

## 4. 구현 방식

### 근거 기반 답변

공공기관 정보를 정리한 지식베이스를 사용합니다.

질문과 관련된 정보가 있는 경우 해당 내용을 찾아 LLM의 답변에 참고할 수 있도록 전달합니다.

```text
사용자 질문
    ↓
관련 정보 검색
    ↓
지식베이스 내용 전달
    ↓
LLM 답변 생성
    ↓
출처 표시
```

현재 지식베이스에는 주요 생활 관련 정보를 카드 12장, 출처 9곳으로 정리해 사용하고 있습니다.

출처 링크는 모델이 직접 생성하기보다는 서버에서 관리된 정보를 사용하도록 구성했습니다.

### 답변 구성

답변은 사용자가 실제 행동으로 이어갈 수 있도록 다음 정보를 중심으로 구성합니다.

```text
① 결론
② 필요한 것
③ 어디서 / 어떻게
④ 주의사항
⑤ 출처
```

### 한 번의 응답으로 처리하기

후속 질문과 방문할 기관은 별도의 API 호출 없이 **답변과 같은 응답에 함께** 받습니다. 무료 사용량과 응답 지연을 늘리지 않기 위한 구성입니다.

```text
답변 본문...

<<<PLACE>>>
정형외과 | 뼈·관절·근육 부상
가정의학과 | 전반적인 확인과 진료과 안내
<<<NEXT>>>
진료비는 얼마나 나오나요?
건강보험이 적용되나요?
```

방문할 기관은 최대 3곳까지 받으며, 각 줄은 `검색어 | 안내 이유` 형식입니다. 의료 질문에서는 진료과 이름을 받고, 하나로 좁혀지지 않으면 여러 줄로 받습니다.

### 창구용 문장과 번역

두 기능 모두 같은 서버 함수를 사용하며 용도에 따라 요청을 구분합니다.

| 기능 | 처리 내용 |
|---|---|
| 창구용 문장 | 대화를 읽고 한국어 문장과 사용자 언어 번역을 한 번의 응답으로 함께 생성 |
| 번역기 | 대화 기록을 사용하지 않고 입력된 문장만 번역 |

### 시설 안내

대화 내용과 사용자의 위치를 바탕으로 관련 시설을 찾을 수 있도록 구성했습니다.

위치 정보는 사용자가 버튼을 눌렀을 때만 요청하며, 시설 검색이 어려운 경우에는 지도 서비스의 딥링크를 통해 외부 지도 서비스로 이동할 수 있습니다.

### 외부 요청

웹폰트, 아이콘 CDN, 지도 SDK 등 외부에서 불러오는 리소스를 사용하지 않습니다. 아이콘은 문서 안에 SVG로 포함되어 있습니다.

네트워크 상태가 좋지 않은 환경에서도 기관 목록과 전화번호를 확인할 수 있도록 하기 위한 구성입니다.

### 개인정보 처리

서비스는 별도의 로그인이나 데이터베이스를 사용하지 않는 구조로 구성했습니다.

대화 기록은 브라우저의 `localStorage`에 저장하며 서버로 전송하지 않습니다.

사용자의 이름이나 전화번호와 같은 식별 정보는 창구용 문장에 자동으로 포함하지 않도록 했습니다.

API Key는 클라이언트에 직접 노출하지 않고 서버리스 함수에서 사용합니다.

## 5. 주요 기술

- **Frontend:** HTML / CSS / JavaScript (외부 라이브러리 없음)
- **Backend:** Vercel Serverless Functions
- **LLM:** Gemini API
- **Knowledge Base:** 자체 정리한 생활·행정 관련 정보
- **지도:** 지도 서비스 딥링크 및 시설 검색
- **음성 입력:** Web Speech API
- **배포:** Vercel

## 7. 현재 한계

현재 서비스가 모든 생활 문제를 해결할 수 있는 것은 아닙니다.

지식베이스에 포함된 정보의 범위가 제한되어 있기 때문에 관련 정보가 없는 질문에서는 일반적인 LLM 답변에 의존할 가능성이 있습니다.

진료과 안내는 해당 문제로 일반적으로 방문하는 곳을 알려주는 것이며 진단이 아닙니다. 실제 진료과 배정은 기관 접수처에서 확인해야 합니다.

또한 지원자 매칭과 요청서의 실제 전송 기능은 아직 구현되지 않았으며, 일부 지도 기능도 계정 설정에 따라 제한될 수 있습니다.

현재 단계에서는 **외국인이 생활 문제를 질문하고, 관련 정보와 다음 행동을 한 번에 확인할 수 있는 서비스의 형태를 구현하는 것**에 초점을 두었습니다.

## 8. 실행 방법

```bash
git clone https://github.com/seojae02/nabi.git
cd nabi
npm install
```

루트 디렉터리에 `key.env` 파일을 생성합니다.

```ini
gemini_api="YOUR_API_KEY"
```

개발 서버를 실행합니다.

```bash
npm run dev
```

기본 실행 주소:

```text
http://localhost:4321
```

## 10. 프로젝트 목표

Nabi는 외국인이 한국 생활에서 문제를 해결할 때 여러 서비스를 따로 찾아다니는 과정을 줄이고,

**"무엇을 해야 하는지 → 무엇을 준비해야 하는지 → 어디로 가야 하는지 → 어떻게 말해야 하는지"**

를 한 흐름 안에서 확인할 수 있도록 하는 것을 목표로 합니다.
