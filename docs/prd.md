## 1. 서비스 개요

### 한 줄 소개

> **외국인이 한국 생활에서 마주하는 문제를 자기 언어로 물어보면, 근거 있는 정보를 쉬운 말로 설명해주고, AI만으로 부족할 때 언어 지원자나 관련 기관까지 연결해주는 생활 지원 서비스**

### 핵심 가치

**질문 → 근거 있는 답변 → 행동 가능한 안내 → 필요 시 사람/기관 연결**

v1의 "분야 선택 → AI 상담" 구조에서 **질문이 먼저, 분야는 보조**로 순서를 바꾼다. 사용자는 자기 문제가 어느 분야에 속하는지 모르는 경우가 많기 때문이다.

## 2. 문제 정의

한국에 거주하는 외국인은 병원, 부동산, 행정 등 일상생활에서 전문적인 의사소통이 필요한 상황을 자주 마주한다.

단순히 시설의 위치를 알려주거나 문장을 번역하는 것만으로는 실제 문제가 해결되지 않는다.

예를 들어:

- 병원에서 접수나 기본적인 의사소통이 어려움
- 부동산 계약 과정에서 한국의 용어나 절차를 이해하기 어려움
- 행정 업무에서 비자·서류·신청 절차를 이해하기 어려움
- 필요한 정보를 어디에서 찾아야 하는지 모름
- 검색해서 찾은 정보가 최신인지, 자신의 체류자격에 해당하는지 판단하기 어려움

### 왜 범용 AI 챗봇으로는 부족한가

이 서비스의 존재 이유는 아래 세 가지다. **이 중 하나라도 빠지면 범용 챗봇과 차별화되지 않는다.**

1. **근거**: 한국 공공기관의 실제 정보(하이코리아, 정부24, 건강보험공단 등)를 출처와 함께 제시한다.
2. **행동 가능성**: "조건에 따라 다릅니다"가 아니라 필요 서류 목록, 방문 기관, 확인 체크리스트를 제시한다.
3. **연결**: 정보로 해결되지 않는 문제는 사람이나 기관으로 넘긴다.

## 3. 타겟 사용자

### 페르소나

**한국에 거주하거나 방문하는 외국인**

v1에서 페르소나를 "한국어가 어느 정도 가능한 사람"으로 한정했으나, 이는 다국어 부담을 회피한 정의였다. v2에서는 **한국어를 전혀 못 하는 사용자도 1차 타겟**으로 포함한다.

### 주요 상황

- 한국어를 못 하거나, 일상 회화는 가능하지만 전문 용어·절차는 어려움
- 병원, 부동산, 행정 등 특정 분야에서 도움 필요
- 필요한 정보를 한국어로 검색하는 데 어려움
- 문제 해결을 위해 누구에게 문의해야 하는지 모름

### 사용 맥락 (중요)

주 사용 환경은 **모바일, 현장, 급한 상황**이다. 병원 접수대 앞, 부동산 사무실, 출입국관리사무소 대기줄에서 꺼내 쓰는 서비스다.

→ **모바일 우선(mobile-first)으로 설계한다.** 데스크톱은 반응형 대응만 한다.

## 4. 핵심 서비스 구조

```text
외국인 사용자
      ↓
  언어 선택 (최초 1회, 이후 변경 가능)
      ↓
  질문 입력  ←──────────────┐
      │                     │
      │  (선택) 분야 카드로 시작  │
      ↓                     │
  AI 분야 판별 + 답변         │
      ↓                     │
  근거 출처 + 행동 안내        │
      ↓                     │
  추가 질문 ─────────────────┘
      ↓
  해결되지 않는 경우
      ↓
  언어 지원자 또는 전문기관 연결
```

v1의 4단계 선형 흐름과 달리, **AI 상담은 멀티턴 루프**다. 사용자는 반드시 후속 질문을 하기 때문이다.

## 5. 핵심 분야

MVP 대상은 **의료 · 부동산 · 행정** 3개다.

분야는 **필터이자 힌트**이지 필수 관문이 아니다. 사용자가 분야를 선택하지 않고 바로 질문하면 AI가 분야를 판별한다.

### 🏥 의료

병원·약국·건강보험 관련 정보를 제공한다.

예시 질문:
- "감기 증상이 있는데 어디로 가야 하나요?"
- "영어가 가능한 병원을 찾고 싶어요."
- "병원에서 접수할 때 뭐라고 말해야 하나요?"
- "외국인도 건강보험이 적용되나요?"

### 🏠 부동산

집 구하기·계약·주거 관련 정보를 제공한다.

예시 질문:
- "외국인도 전세 계약을 할 수 있나요?"
- "보증금과 관리비가 무슨 뜻인가요?"
- "계약 전에 무엇을 확인해야 하나요?"
- "집주인이 보증금을 안 돌려줘요."

### 🏛️ 행정

비자·서류·신청·공공서비스 관련 정보를 제공한다.

예시 질문:
- "주소가 바뀌었는데 어디에 신고해야 하나요?"
- "외국인등록증을 재발급받으려면 어떻게 하나요?"
- "이 행정 업무는 어디에서 처리하나요?"

### 제외된 분야

| 분야 | 상태 | 사유 |
|---|---|---|
| 💼 취업 | **MVP 제외** | 3개 분야로도 데모에 충분하며, 근로계약·임금체불은 사실상 법률 영역이라 별도 근거 데이터가 필요하다. |
| ⚖️ 법률 | **미정의 (인지된 공백)** | 부동산·취업 질문의 상당수가 실제로는 법률 문제로 넘어간다. MVP에서는 **법률성 질문을 감지하면 즉시 기관 연결로 에스컬레이션**한다(9.3 참조). |

## 6. AI의 역할과 한계

AI는 전문적인 판단을 대신하지 않는다. **질문을 이해하고, 검증된 정보를 쉬운 말로 설명하며, 필요할 때 적절한 도움으로 넘기는 중간 역할**을 한다.

### 6.1 AI가 담당하는 역할

1. 사용자의 질문에서 분야를 판별
2. 근거 데이터에서 관련 정보를 찾아 **사용자 언어로** 설명
3. **행동 가능한 형태**로 안내 (필요 서류 / 방문 기관 / 확인 체크리스트)
4. 답변의 **출처를 함께 표시**
5. 에스컬레이션 조건 충족 시 사람/기관 연결 제안

### 6.2 근거 데이터 (신설)

**답변은 아래 소스에 근거해야 하며, 근거를 찾지 못하면 "확인이 필요하다"고 답하고 기관 연결로 넘긴다.** 모델의 기억에만 의존한 답변을 금지한다.

| 분야 | 1차 소스 |
|---|---|
| 행정 | 하이코리아(HiKorea), 정부24, 법무부 출입국·외국인정책본부 |
| 의료 | 건강보험공단 외국인 안내, 응급의료포털 E-Gen, 지자체 외국인 진료 안내 |
| 부동산 | 국토교통부 실거래가/전월세 안내, 대한법률구조공단 임대차 안내, 주택도시보증공사(HUG) 보증 안내 |

MVP 구현 방식: 위 소스의 핵심 문서를 수집·정제해 **로컬 지식베이스로 구축하고 RAG로 검색**한다. 실시간 API 연동은 후순위다.

### 6.3 답변 형식 규칙

모든 답변은 아래 구조를 따른다.

```
① 한 문장 결론
② 필요한 것 (서류 / 준비물 / 조건)
③ 어디서 / 어떻게
④ 주의사항
⑤ 출처 링크
```

**나쁜 예시 (v1 PRD에 있던 답변):**
> "외국인도 조건에 따라 전세 계약을 할 수 있습니다. 다만 체류자격이나 계약 조건에 따라 확인해야 할 사항이 있을 수 있습니다."

이 답변은 아무 정보도 주지 않는다.

**좋은 예시 (v2 기준):**
> **네, 외국인도 전세 계약이 가능합니다.**
>
> **필요한 서류**
> - 외국인등록증 (또는 여권 + 국내거소신고증)
> - 외국인등록 사실증명 — 정부24 또는 출입국사무소에서 발급
>
> **계약 전 반드시 확인할 것**
> - 등기부등본에서 근저당·가압류 확인
> - 임대인 실소유자 여부 확인
> - 전세보증금 반환보증(HUG) 가입 가능 여부
>
> **주의**
> 계약 후 14일 이내에 관할 주민센터에서 **확정일자**를 받아야 보증금 우선변제권이 생깁니다. 이걸 놓치면 보증금을 못 돌려받을 수 있습니다.
>
> 📎 출처: 대한법률구조공단 주택임대차 안내 / HUG 전세보증금반환보증

### 6.4 면책 및 안전 정책 (신설)

비자·의료·계약은 **잘못된 정보의 피해가 실제로 크다.** 다음을 강제한다.

- 모든 답변 하단에 면책 문구를 고정 노출한다.
  > ⓘ 이 정보는 참고용입니다. 최종 확인은 관련 기관에 문의하세요.
- 아래 유형의 질문에는 **AI가 직접 답하지 않고 기관 연결로 전환**한다.
  - 진단·처방·복약 지시를 요구하는 의료 질문
  - 개별 사건의 법적 판단을 요구하는 질문 (소송, 분쟁, 처벌 여부)
  - 체류자격 심사 결과를 예측해달라는 요청
- 응급 상황 키워드(호흡곤란, 의식 없음, 심한 출혈 등) 감지 시, 답변보다 먼저 **119 / 1339 안내를 최상단에 노출**한다.

### 6.5 에스컬레이션 조건 (신설)

v1의 "AI가 추가 도움이 필요한지 판단"은 기준이 없었다. v2에서는 아래 중 **하나라도 해당하면** 연결 CTA를 노출한다.

1. 근거 데이터에서 관련 정보를 찾지 못함
2. 6.4의 금지 유형에 해당
3. 같은 주제로 3턴 이상 대화가 이어짐 (해결 실패 신호)
4. 사용자가 직접 "사람과 이야기하고 싶다"고 요청
5. 답변에 대면 절차가 포함됨 (통역이 실제로 필요한 상황)

## 7. 다국어 (MVP 필수 — v1 대비 승격)

v1은 다국어를 UI 원칙에만 두고 MVP 필수 목록에서 빠뜨렸다. **외국인 대상 서비스에서 이는 서비스 자체의 실패**를 의미한다.

### 지원 범위 (MVP)

| 언어 | 상태 |
|---|---|
| 🇺🇸 English | **필수** |
| 🇰🇷 한국어 | **필수** |
| 🇻🇳 Tiếng Việt | 확장 (구조만 준비) |
| 🇨🇳 中文 | 확장 (구조만 준비) |

### 요구사항

- **첫 진입 시 언어 선택**을 노출한다. 브라우저 `navigator.language`로 기본값을 추정하되 변경 가능해야 한다.
- 모든 UI 문자열은 코드에 하드코딩하지 않고 **i18n 리소스 파일**로 분리한다. (언어 추가가 리소스 추가만으로 가능해야 함)
- **AI 답변도 사용자가 선택한 언어로 출력**한다. 시스템 프롬프트에 대상 언어를 주입한다.
- **한국어 원문 병기**: 기관명·서류명·주소는 번역문과 함께 한국어 원문을 표시한다. 사용자가 창구에서 그대로 보여줄 수 있어야 하기 때문이다.
  > 외국인등록 사실증명 (Certificate of Alien Registration)

## 8. 사람/기관 연결

### 8.1 목적

> 사람 연결의 목적은 전문적인 판단을 대신하는 것이 아니라 **언어 장벽과 의사소통 문제를 해결하는 것**이다.

### 8.2 공급 측 정의 (신설 — v1의 최대 공백)

v1은 "Nguyen ○○"을 매칭해주면서 **이 사람이 어디서 오는지를 정의하지 않았다.** 4개 화면이 전부 수요자 화면이었다.

**MVP에서의 정직한 범위:**

| 구분 | MVP 범위 |
|---|---|
| 언어 지원자 풀 | **시드 데이터 5~8명** (운영자가 수동 등록) |
| 매칭 | 언어 · 분야 · 가능 시간 기준 **규칙 기반 필터링** |
| 지원자 가입/검증 플로우 | **MVP 제외** (Post-MVP) |
| 실시간 수락/거절 | **MVP 제외** (Post-MVP) |

> ⚠️ **MVP의 지원자 매칭은 시드 데이터 기반 시뮬레이션이다.** 화면과 발표 자료에 이 사실을 명시한다. 실제 매칭인 것처럼 보이게 하지 않는다.

기관 연결은 시뮬레이션이 아니다. **공개된 실제 기관 정보(전화번호·주소·운영시간)를 그대로 제공**한다. 이 부분은 MVP에서도 진짜로 동작한다.

- 외국인종합안내센터 **1345** (20개 언어 지원)
- 지자체 외국인주민지원센터
- 대한법률구조공단 **132**
- 응급의료정보센터 **1339**

### 8.3 연결의 실체 (신설 — v1에서 미정의)

v1은 `[연결 시작]` 버튼 이후를 정의하지 않은 채 채팅·통역·예약·위치공유를 전부 후순위로 뺐다. **연결의 실체가 비어 있었다.**

MVP에서는 **비동기 요청서 방식** 하나로 닫는다.

```text
[연결 시작] 클릭
      ↓
요청서 자동 생성
  · 필요 언어 · 분야
  · 대화 요약 (AI가 생성)
  · 필요한 도움 · 희망 시간
      ↓
확인 화면 (사용자가 수정 가능)
      ↓
[요청 보내기]
      ↓
접수 완료 화면
  "24시간 이내에 연락드립니다"
  + 즉시 도움이 필요하면 → 1345 바로 전화
```

핵심은 **막다른 길을 만들지 않는 것**이다. 비동기 요청이 접수되더라도 항상 **지금 당장 전화할 수 있는 번호**를 함께 제공한다.

## 10. UI/UX 원칙

### 1. 질문이 먼저, 분야는 나중
사용자는 자기 문제가 어느 분야인지 모른다. 분야 선택은 도움이 되는 지름길이지 통과해야 하는 관문이 아니다.

### 2. 대화는 끊기지 않는다
답변 하나로 끝내지 않는다. 후속 질문이 항상 가능하고, 무엇을 물어야 할지도 제안한다.

### 3. 쉬운 언어 + 한국어 원문 병기
전문 용어는 쉽게 설명하되, 창구에서 보여줘야 할 단어는 한국어를 함께 남긴다.

### 4. 근거를 밝힌다
모든 답변에 출처와 면책 문구를 표시한다. 확실하지 않으면 확실하지 않다고 말한다.

### 5. 단계적인 도움 — 막다른 길 없음
AI → 사람 → 기관으로 이어지고, 어느 단계에서도 "지금 당장 할 수 있는 것"이 남아 있어야 한다.

### 6. 모바일 우선
현장에서 한 손으로 쓰는 서비스다. 터치 타겟 최소 44px, 주요 CTA는 엄지 도달 범위에 배치한다.

## 11. 개인정보 및 데이터 정책 (신설)

체류자격·건강 상태는 개인정보보호법상 **민감정보**에 해당할 수 있다. v1에는 계정 개념도, 데이터 정책도 없었다.

**MVP 정책: 최소 수집 · 비로그인 · 기기 보관**

> 초판에서는 "세션 내에서만 유지"였으나, 대화 기록 화면을 구현하면서 기기 보관으로 바꿨다.
> 서버 저장이 없다는 원칙은 그대로다. **화면의 개인정보 고지도 같이 수정했다** —
> 저장하면서 "저장하지 않는다"고 표시할 수는 없다.

| 항목 | MVP 정책 |
|---|---|
| 회원가입 / 로그인 | **없음** |
| 대화 내역 저장 | **이 기기의 브라우저(localStorage)에만 저장. 서버 전송·저장 없음.** 설정에서 언제든 전체 삭제. 최대 40개 |
| 연결 요청서 | 연락처는 요청 처리 목적으로만 사용, 처리 후 파기 |
| 수집 금지 항목 | 여권번호, 외국인등록번호, 상세 진단명 |
| 안내 | 첫 진입 시 "개인정보를 저장하지 않습니다"를 사용자 언어로 고지 |

AI에게 개인 식별 정보를 입력하지 말라는 안내를 입력창 근처에 표시한다.

## 15. 발표용 핵심 메시지

### 한 줄 소개

> **외국인이 자기 언어로 물어보면, 한국 공공기관 정보에 근거해 무엇을 준비하고 어디로 가야 하는지 알려주고, 그래도 어려우면 사람과 기관까지 연결해주는 생활 지원 서비스입니다.**

### 서비스 흐름

> **자기 언어로 질문 → 근거 있는 답변 → 행동 가능한 안내 → 필요 시 사람/기관 연결**

### 차별점 (3가지)

단순한 번역기도, 지도 서비스도, 범용 챗봇도 아니다.

1. **근거** — 하이코리아·법률구조공단 등 실제 공공 정보에 기반하고 출처를 밝힌다
2. **행동 가능성** — "조건에 따라 다릅니다"가 아니라 필요 서류와 갈 곳을 알려준다
3. **연결** — 정보로 안 되는 문제는 사람과 기관으로 넘긴다. 막다른 길을 만들지 않는다

### 데모 시나리오 (권장)

> 베트남 사용자가 영어로 "집주인이 보증금을 안 돌려줘요"라고 입력
> → AI가 부동산/법률 문제로 판별
> → 확정일자·내용증명 절차를 영어로 설명 + 한국어 원문 병기 + 출처 표시
